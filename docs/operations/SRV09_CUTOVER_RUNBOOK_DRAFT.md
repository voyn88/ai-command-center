## 1. Purpose and scope

This is the operator runbook for cutting the server deployment's runtime
store over from SQLite (authority today) to PostgreSQL (authority after
cutover). It assumes `VOYN-W0-AICC-SRV-01a` (PostgreSQL foundation) and
`VOYN-W0-AICC-SRV-01B` (all-33-tables mirror) are both merged, and that the
service is currently running with SQLite as authority and PostgreSQL as a
dual-write mirror.

## 2. Current state

- Roles: `aicc_migrator`, `aicc_app`, `aicc_worker`, provisioned by
  `command_center/db/roles.py:render_bootstrap` /
  `render_table_grants`. See `docs/postgres-foundation.md`.
- Pooling: `command_center/db/pool.py:open_pool()` opens one pool per
  process explicitly at startup; `get_pool()` returns it. There is no
  supported way to swap it without a restart.
- Migrations applied: `0001_initial`, `0002_queue_claim`,
  `0003_worker_enrollment`.
- Generic PostgreSQL machinery lives in `aios-db`, consumed only through
  `command_center/db/adapter.py`.

## 3. Schema correspondence baseline

Per `docs/srv01b-schema-map.md`: 33 domain tables on both sides, 1:1
correspondence, no orphans either direction. 114 of 395 columns change type
crossing the boundary and 105 of those need value conversion, not just a
type label change. The two classes that matter operationally:

- 75 `TEXT` → `timestamptz` columns. `command_center/models.py:iso_now()`
  writes naive local time with no offset. A backfill that loads that string
  into `timestamptz` gets it interpreted in the importer's session
  timezone — silent skew, unrecoverable after the fact because the
  original offset was never stored.
- 7 identity columns (`run_event.id`, `completion_event.id`,
  `completion_validation.id`, `proposal_event.id`, ...) moving from SQLite
  `INTEGER PRIMARY KEY` to `bigint GENERATED ALWAYS AS IDENTITY`.

## 4. Preflight (A0)

Before backfill:

1. Confirm `python -m command_center.db status` reports every PostgreSQL
   migration applied and its checksum verified.
2. Confirm `GET /readyz` is `200` (schema matches
   `EXPECTED_SCHEMA_VERSION`, database reachable).
3. Confirm the three-role grant matrix with
   `tests/db/test_postgres_integration.py`.
4. Take a verified backup: `scripts/aicc_pg_backup.sh --out-dir
   /var/backups/aicc --verify --keep 14`.

## 5. Backfill / dual-write posture

Every domain table already dual-writes through the mirror stores under
`command_center/db/*_store.py`, coordinated by the shared contract in
`command_center/record_mirror.py` (`RecordMirror.upsert`, safe to run more
than once) and `command_center/db/table_mirror.py` /
`command_center/db/mirror_support.py`. The direction today is SQLite
(authority) → PostgreSQL (mirror): every `_mirror_*` call in
`command_center/runtime/db/schema.py` fires after the SQLite write commits.

Run the backfill importer once against a quiesced or replayable window,
then let dual-write carry new rows.

## 6. Reconciliation gate

`tests/db/test_schema_correspondence.py` and `tests/db/test_mirror_coverage.py`
are the two automated gates: the first proves structural correspondence
against a real PostgreSQL server, the second proves every schema table is
either mirrored or has a dated, task-owned entry in
`UNMIRRORED_SCHEMA_TABLES`. Both must be green in CI on the commit being
cut over.

## 7. Read path

Reads stay on SQLite through cutover day. There is no read-switch
mechanism in this codebase yet; flipping reads to PostgreSQL is out of
scope for this runbook.

## 8. Cutover sequence

1. Freeze new work admission (stop the dispatcher / queue enqueue).
2. Wait for `run.state` to reach a terminal value for every in-flight run.
3. Run the backfill importer's final incremental pass.
4. Flip the application's write authority flag to PostgreSQL.
5. Resume admission.

## 9. Point of no return

The point of no return is the write-authority flip in step 8.4. Before it,
everything is reversible by simply not flipping the flag. After it, new
writes land in PostgreSQL as authority.

## 10. Rollback plan

If anything looks wrong after the flip: flip the write-authority flag back
to SQLite. Because SQLite was authority until the flip and dual-write was
still running, SQLite should be at most one backfill pass behind.

## 11. Backup and operational safety

Nightly `scripts/aicc_pg_backup.sh` and the `scripts/aicc_pg_restore.sh`
drill (`test_backup_restore_drill_round_trips_data`) are already proven
end to end. No changes needed for cutover beyond running the drill once
immediately before step 8.

## 12. Post-cutover validation

Confirm `/readyz` stays `200`, confirm the queue keeps draining
(`VOYN-W0-AICC-SRV-06` watchdog), and watch error rates on the API for one
full business day before decommissioning the SQLite write path.
